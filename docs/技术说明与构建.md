# Heat CG Fix / 热度过场动画修复

Experimental single-file runtime fix for one identified Need for Speed Heat cutscene performance issue.

Co-created by the player who reported and tested the issue, and **弦灯 / Chordlight (OpenAI Codex)**. Player credit pending their chosen public name. This project is not affiliated with EA, NVIDIA, Intel, or OpenAI.

## 安装 / Install

1. 完全退出游戏。将发行包中的 **dinput8.dll** 放到 `NeedForSpeedHeat.exe` 同一目录。
2. 从 Steam 原来的“开始”按钮启动。不需要之前的修复启动器、管理员权限或额外启动参数。
3. 查看同目录自动生成的 `HeatCGFix.log`。出现 `APPLIED` 或 `ACTIVE` 表示修复已生效。

已在本机通过普通 Steam 启动验证：游戏会自动加载此 DLL，日志和独立内存读回均确认修复生效。完整验证情况见 `VALIDATION.md`。

Exit the game, place the release `dinput8.dll` beside `NeedForSpeedHeat.exe`, then launch normally through Steam. An `APPLIED` or `ACTIVE` line in `HeatCGFix.log` confirms runtime activation.

**如果已有同名 DLL，请不要覆盖。** 其他 Mod、代理加载器或图形工具可能使用同一入口；本版本不支持代理链。EA app 单独启动和其他发行版本尚未测试。

If a `dinput8.dll` already exists, do not overwrite it. Proxy chaining is not implemented. Standalone EA app launch and other distributions are untested.

## 卸载 / Uninstall

退出游戏，删除安装的 `dinput8.dll`；日志也可以删除。游戏 EXE 从未被修改。不要同时使用旧的 CG 修复启动器，以免混淆验证结果。

Exit the game and remove the installed DLL. The log may also be removed. No executable on disk, affinity, efficiency mode, registry entry, or system setting is changed.

## Supported executable

- x64 executable version observed: **1.0.60.7040**
- SHA256: `573f91d6984b5dcfbbeacc7ef92ca2d89b46a76b328d71411747b17cd187106c`
- Runtime instruction RVA: `0x0e6d749b`
- Original instruction: `66 87 05 5D 99 29 02`
- Replacement: `66 89 05 5D 99 29 02`

The worker checks the host name, disk executable SHA256, PE layout and all seven runtime instruction bytes. It waits up to five minutes for the protected executable to initialize. Unsupported builds are left unmodified. It resolves the six DirectInput exports by name and loads the original library using its absolute Windows system-directory path.

## Evidence and limitations

On the initial test system (i5-14600KF, RTX 5060, Windows 11), severe prerendered-cutscene stuttering occurred while real-time driving and the menu were smooth. ETW sampling found 108,210 of 365,878 game samples (~29.6%) at the instruction immediately following a memory XCHG in a boolean-decoder-like routine; the corresponding menu trace had zero samples there. Sampling attribution is approximate and can skid.

The memory operand spans a 64-byte cache-line boundary. Memory XCHG has implicit atomic locking. Replacing it with MOV preserves the global store while removing the exchange's read and atomic ordering. The old AX value is overwritten before subsequent use within this routine. The player reported smooth cutscenes after the one-byte runtime change, and subsequently confirmed map loading and driving worked.

**This is not proof of safety on every configuration.** Concurrent observers of the global and the loss of atomic ordering have not been exhaustively analyzed. Long sessions, additional game content, other CPUs/GPUs and other Windows versions remain unverified. This is a targeted workaround, not a general FPS or CPU tuning mod. No license/authentication check is intentionally bypassed or modified.

## Build

Use Zig 0.15.2 on Windows:

```powershell
pwsh -File source/build.ps1 -Zig C:/path/to/zig.exe
```

The output is `release/dinput8.dll`. Only that DLL is required for installation. `proxy_smoke_test.exe` is a developer test executable, not part of the game installation.

Source and binary are provided without game executable bytes or game assets. The project has no network, telemetry or automatic-update component.
